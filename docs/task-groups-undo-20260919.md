# 업무 그룹 / 직전 변경 되돌리기

2026-09-19 구현. 운영 DB 적용 완료(16:23 KST), 프런트 배포 진행.

- 작업 위치: `pocket-copy-release-20260919` (기존 개발 폴더의 미커밋 변경과 분리).
- 표/간트 선택 툴바의 업무 그룹 → 이름 입력. 기본 접힘. 그룹 체크박스로 소속 업무 전체 선택 후 그룹 해제.
- 그룹은 실제 업무가 아니다. 완료 집계와 날짜를 추가하거나 합치지 않는다. 요약 간트는 실제 일정 날짜의 합집합만 표시하며 빈 날짜를 연결하지 않는다.
- 그룹 이름/소속은 DB 공유 데이터. 접힘/펼침은 개인 화면 메모리. 고객 공개 설정은 변경하지 않는다. 고객 read projection에 내부 그룹 이름을 추가하지 않았다.
- 그룹 생성/해제는 원자적 업무 배치 저장으로 1회 최대 40개. 부분 선택 후 해제하면 그 업무만 묶음에서 빠진다. 그룹 이동은 기존 그룹에서 선택 업무만 새 그룹으로 옮긴다.
- 알림 옆 되돌리기 또는 Ctrl/Cmd+Z: 현재 탭에서 저장한 직전 업무 변경 1회. 수정·일정·그룹·생성·복사·소프트 삭제 지원. 회의록/확인요청 등 다른 도메인은 제외. 새로고침/로그아웃하면 취소 핸들을 폐기한다.
- 40건씩 나뉜 기존 일괄 작업/복사는 같은 사용자 동작의 ID를 묶어 취소한다(최대 1,000개). 입력칸의 기본 텍스트 실행취소는 가로채지 않는다.
- 서버가 감사 로그의 before/after를 조회한다. 다른 사람의 변경, 이후 수정된 버전, 권한 없는 프로젝트는 거절. 클라이언트가 복원할 스냅샷을 전달하지 않는다. 재시도는 동일 undo ID로 중복 방지.
- 보류/일정 정규화 트리거 이후 안전한 private 트랜잭션 컨텍스트를 통해 원본 스냅샷을 복원한다. row_version은 되감지 않고 증가한다. 복구 자체도 감사 로그에 남는다.

## 검증 / 배포 순서

1. `frontend`: `npm test`, `npm run test:supabase`, `npm run build`, `npm run test:review-ui`.
2. DB 마이그레이션 `20260919072346_task_groups_and_undo.sql`만 검토·적용. 다른 작업 폴더의 미배포 마이그레이션을 함께 적용하지 않는다. 운영의 구형 업무 로그 함수와 로컬의 페이지네이션 함수를 모두 지원한다.
3. 적용 후 보안 advisor 및 실제 권한별 read/undo 계약 확인. 운영 업무를 테스트 목적으로 변경하지 않는다.
4. 프런트엔드 배포. 이전 버전도 새 nullable 열과 호환되므로 DB → 프런트 순서.

운영 업무 데이터는 변경하지 않았다. 스키마/API만 적용했으며 PGlite 격리 DB로 쓰기·복구를 검증했다. 운영 보안 advisor 경고는 적용 전후 동일(기존 public definer 9건 및 비밀번호 보호 설정 1건)하며 별도 점검 대상이다.
