# 포켓 · NS 운영 권한 기준 (2026-10-01)

일반 운영 기능은 포켓/NS 모두 제공한다. NS는 서버의 활성 프로젝트 EDIT 멤버십과 페이지 권한을 유지하며, 운영자 계정으로 승격하지 않는다. 운영 DB의 UND·무극·포켓컴퍼니·메디신피아 모두 NS EDIT 멤버십을 확인했다.

| 영역 | 포켓 / NS 공통 | 남기는 경계 |
|---|---|---|
| 업무·일정·간트 | 생성·수정·복사·그룹·순서·보류일정·삭제·되돌리기 | 고객 읽기 전용, 충돌 검사 |
| 고객 공개 | 신규/개별 수정/체크박스 일괄 숨김·재공개 | NS는 CLIENT ↔ PROJECT_TEAM, POCKET_ONLY 불가 |
| 프로젝트 | 생성·견적/일정 불러오기·착수일 저장 | 활성 프로젝트와 EDIT 권한 검사, 착수일 외 임의 관리 필드 변경 불가 |
| 확인요청·회의록 | 작성·수정·처리, 회의록 공개/숨김 | 고객 공개 범위/페이지 검사, 포켓 전용 자료 차단 |
| 블로그·KPI·월별 보고서 | 등록·수정·삭제/게시 등 기존 운영 기능 | 프로젝트 권한과 공개된 고객용 조회만 허용 |
| 고객 권한관리 | 담당 프로젝트 고객 계정 생성·페이지 권한 배정·제거 | 내부 계정 덮어쓰기 및 NS의 전체 계정 상태 변경 불가 |
| 계정대장 | 기존 프로젝트별 관리·명시적 비밀번호 열람 | 비밀정보 자동 출력/로그 금지, 열람 감사 유지 |

## 변경 이유

고객 숨김은 `TasksView`의 포켓 전용 버튼 조건과 `private.mutate_task`의 NS 공개 범위 변경 차단이 동시에 원인이었다. 개별 수정 팝업에는 두 운영자 모두 공개 범위 입력 자체가 없었다. 회의록도 비슷한 별도 차단이 있었고, 착수일은 Supabase로 조회하면서 Sheets로 쓰는 경로여서 단순 버튼 허용으로 해결할 수 없었다.

## 구현과 검증

- 공통 UI 정책은 `operatorCapabilities.js`; 실제 권한은 RLS/RPC에서 재검증한다.
- 기존 업무/회의록의 포켓 전용 행을 NS가 ID로 직접 수정·공개·삭제하지 못하도록 행 가시성도 확인한다. 기존 자료의 공개 범위를 일괄 변경하지 않는다.
- 착수일 RPC는 `start_date`만 허용하고 행 버전, 저장 ID, 프로젝트 감사 로그를 유지한다. 프로젝트 테이블의 임의 UPDATE 권한은 NS에 열지 않는다.
- NS 생성/개별 편집/일괄 숨김·재공개/재시도/감사/되돌리기, 고객 실제 조회 차단, 포켓 전용·읽기 전용 차단을 DB 회귀로 검증한다. PC·모바일 테스트는 실제 컴포넌트를 역할별로 실행한다.
- 비활성 레거시 콘텐츠/파일 원장과 실행계획의 관리용 HTML 가져오기 RPC, DB·배포·백업 관리 권한은 이번 운영 권한 확대 대상이 아니다.
